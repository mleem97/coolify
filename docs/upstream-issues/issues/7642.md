[Zur Gesamtübersicht](../README.md)

## Aufarbeitung: SurrealDB als native Datenbank mit geprüften Speicher-Backends integrieren

**Bereich:** Datenbankintegration / SurrealDB / Persistenz · **Priorität:** P2 · **Bewertung:** Erweiterung

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Die Diskussion verlangt eine vollständige native Datenbankintegration mit Lebenszyklus, Zugangsdaten und persistentem Speicher, ausdrücklich mehr als zusätzliche Compose-Templates. Die ursprünglich gewünschten RocksDB-/TiKV-Varianten sind heute versionsabhängig: Die aktuelle offizielle 4.0-Dokumentation beschreibt SurrealKV als lokalen Speicher und TiKV in einem separaten Serverbuild. Zuerst ist deshalb eine belastbare Versions-/Backendmatrix nötig.

### Reproduktion / Prüfszenario

1. Den vorhandenen Datenbankdialog und die unterstützten Ressourcentypen prüfen; SurrealDB fehlt im untersuchten Stand.
2. Einen isolierten Machbarkeitstest je beabsichtigtem Speicherbackend mit festem Serverimage und gegebenenfalls festem PD-/TiKV-Stand definieren.
3. Daten schreiben, neu starten, exportieren und in eine neue Instanz importieren; für TiKV zusätzlich tatsächlichen erfolgreichen Speicherzugriff nachweisen.

### Befunde

- Der Sponsor präzisiert mehrfach, insbesondere am 04.04.2026, dass ein bloßes Template den Bedarf nicht erfüllt; im Mai fordert er den damals aktuellen v3-Stand.
- app/Enums/NewDatabaseTypes.php enthält keinen SurrealDB-Typ; in den geprüften Modellen, Aktionen und Migrationen wurde keine native SurrealDB-Integration gefunden.
- Die aktuelle offizielle SurrealDB-Migrationsdokumentation erklärt den Wegfall des RocksDB-Backends in 4.0 und den separaten surreal-tikv-Build; das normale Containerimage darf daher nicht blind für beide Varianten verwendet werden.
- Ein Kommentar vom 06.11.2026 berichtet fehlgeschlagene TiKV-Handshakes eigener Templateversuche. Das ist ein zu prüfender Kompatibilitätshinweis, keine validierte generelle Unmöglichkeit.
- 42 Kommentartexte waren abrufbar, während der GitHub-Zähler 44 meldet und die zweite API-Seite leer blieb. Die Ursache dieser Lücke ist unbekannt.

### Umsetzungsschritte

- [ ] Eine konkrete Zielversion und unterstützte Backendkombination festlegen; für historische RocksDB-Anforderungen den Upgrade-/Migrationsweg dokumentieren und keinen freien Backendwechsel am selben Datenverzeichnis anbieten.
- [ ] Nativen Ressourcentyp, Migration, Start/Stop/Restart, Zustandsprüfung, Zugangsdaten, UI und API an die vorhandenen Standalone-Datenbankmuster anbinden.
- [ ] TiKV-Anbindung an einen bestehenden Cluster und vollständige Clusterprovisionierung als getrennte Ausbaustufen behandeln; keine Hochverfügbarkeit aus einer Ein-Host-Compose-Datei ableiten.
- [ ] HTTP/RPC- beziehungsweise WebSocket-Zugang mit Authentisierung und TLS sowie Backup/Restore und Export-/Transferverhalten ausdrücklich spezifizieren.

### Abnahmekriterien und Regressionstests

- [ ] SurrealDB erscheint als native Datenbank und unterliegt denselben Team-/Ressourcenberechtigungen wie bestehende Typen.
- [ ] Jede angebotene Backend-/Versionskombination startet, liest und schreibt erfolgreich und erhält Daten nach Neustart.
- [ ] Backup und Wiederherstellung sind mit realen Daten nachgewiesen; nicht unterstützte Backendwechsel werden verhindert.
- [ ] TiKV wird erst als funktionsfähig angeboten, wenn der Server tatsächlich mit dem Speichercluster arbeitet; reine PD-/TiKV-Healthchecks reichen nicht.

### Offene Fragen und Risiken

- Die gewünschte TiKV-Betriebsform und Zielversion sind noch eine Architekturentscheidung; 2025/2026 vorgeschlagene Imagekombinationen dürfen nicht ungeprüft übernommen werden.
- Die offizielle 4.0-Migration beschreibt irreversible Datenformatänderungen; Entwicklungstests müssen mit Kopien erfolgen.
- Zwei Kommentare sind nicht direkt abrufbar; eine zitierte E-Mail erwähnt einen fehlenden Kommentar, erklärt die Differenz aber nicht sicher.
- Algora-Bountys sind laut Maintainer seit September 2026 beendet.

### Proposed Solution

The root cause is the lack of SurrealDB integration in the Coolify project. Discussions have been ongoing, but a concrete implementation is needed.

To implement SurrealDB with TIKV and RockDB, follow these steps:
1. Add SurrealDB dependency in `package.json`.
2. Create a new file `src/services/surrealdb.ts` with the SurrealDB client setup.
```typescript
// src/services/surrealdb.ts
import { Surreal } from 'surrealdb.js';

const surreal = new Surreal('http://localhost:8000/rpc');
```
3. Update `src/config/database.ts` to include SurrealDB options.
```typescript
// src/config/database.ts
export const databases = {
  // ...
  surrealdb: {
    tikv: {
      // TIKV config
    },
    rockdb: {
      // RockDB config
    }
  }
};
```
Test the implementation by running `npm run start` and verifying SurrealDB connections.
