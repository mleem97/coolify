## Aufarbeitung: Benutzerdefinierte Schutz- und Logging-Labels in PR-Vorschauen erhalten

**Bereich:** Preview / Proxy · **Priorität:** P1 · **Bewertung:** Konkreter Codebefund

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

PR-Vorschauen ersetzen benutzerdefinierte Container-Labels durch neu generierte Labels. Dadurch fehlen manuell eingerichtete Basic-Auth-Middlewares und andere Labels. Die inzwischen integrierte Basic-Auth-Einstellung ist ein eigener, bereits unterstützter Pfad.

### Reproduktion / Prüfszenario

1. Eine Anwendung mit manueller Traefik-Basic-Auth-Middleware und zusätzlichem Logging-Label deployen.
2. PR-Vorschau erstellen und Produktions-/Preview-Labels vergleichen.
3. Beide URLs ohne Zugangsdaten abrufen; für die geschützte Vorschau wird 401 erwartet.

### Befunde

- Die Meldung betrifft beta.309; ein Kommentar bestätigt zusätzlich ein fehlendes logging=promtail-Label.
- ApplicationDeploymentJob::generate_compose_file ersetzt im Zweig pull_request_id != 0 die zuvor gelesenen custom_labels vollständig durch generateLabelsApplication.
- bootstrap/helpers/docker.php übernimmt die integrierten Basic-Auth-Felder bereits in Preview-Router.

### Umsetzungsschritte

- [ ] Benutzerdefinierte Middleware-/Logging-Labels von produktionsspezifischen Router-, Host- und Service-Namen unterscheiden.
- [ ] Preview-spezifische Router erzeugen und nur kompatible benutzerdefinierte Labels samt Middleware-Verweisen übernehmen.
- [ ] Für nicht sicher übertragbare Router-Konfiguration eine sichtbare Validierung anbieten.

### Abnahmekriterien und Regressionstests

- [ ] Manuelle Basic Auth schützt Produktion und Preview; falsche Zugangsdaten werden auf beiden abgewiesen.
- [ ] Zwei gleichzeitige PRs haben getrennte Router und erhalten das Logging-Label.
- [ ] Integrierte Basic Auth, Caddy und Apps ohne eigene Labels bleiben funktionsfähig.

### Offene Fragen und Risiken

- Blindes Zusammenführen kann Produktionsverkehr auf PR-Container lenken.
- Der vollständige manuelle Labelsatz aus der betroffenen Installation fehlt.

### Description

If your project has a traefik middleware for basicauth it won't apply on the PR previews, which could leak information.

Yes, you shouldn't fully count on that to protect important information and should also be doing that on the app itself, but I personally use it as a quick way to protect a project I want to keep private or that I want to share before release, to a client for example.

So, I think that it should also apply to the PR previews as well.

### Minimal Reproduction (if possible, example repository)

1. Make a random web ressource (e.g. a nextjs app)
2. Add a basicauth middleware in the traefik container labels
3. Make sure it works fine
4. Enable PR previews
5. Make a PR and wait for it to build and be online
6. You can access to website via the PR url without any auth
