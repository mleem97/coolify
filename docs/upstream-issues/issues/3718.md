## Aufarbeitung: Appwrite-Funktionsdomains und Wildcard-Routing abstimmen

**Bereich:** Service-Template / Appwrite · **Priorität:** P2 · **Bewertung:** Reproduktion erforderlich

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Der Bericht vermischt falsch zusammengesetzte Appwrite-Domains mit späteren 404-Antworten für korrekt erzeugte Subdomains. Beide Ebenen müssen separat geprüft werden: Domainwerte ohne Schema und Erreichbarkeit der Funktions-/Site-Subdomains durch den Proxy.

### Reproduktion / Prüfszenario

1. Appwrite aus dem aktuellen Template mit einer kontrollierten Basisdomain deployen.
2. Über GitHub eine Funktion erstellen und die generierte Domain prüfen.
3. Funktion über HTTPS abrufen und denselben Host testweise ausdrücklich im Dienst hinterlegen.

### Befunde

- Kommentare verweisen auf frühere URL/FQDN-Verwechslungen und eine teilweise Korrektur über PR 4226.
- Kommentar 2500838990 beschreibt einen Unterschied zwischen Traefik-2- und Traefik-3-HostRegexp-Syntax.
- templates/compose/appwrite.yaml verwendet aktuell _APP_DOMAIN und functions./sites.-Unterdomains mit SERVICE_FQDN_APPWRITE.

### Umsetzungsschritte

- [ ] Aktuelle Magic-Variable-Werte mit Appwrites Anforderungen vergleichen.
- [ ] Ein reproduzierbares Routingbeispiel für die unterstützte Traefik-Version erstellen und Template/Dokumentation darauf abstimmen.
- [ ] Automatisch erzeugte Subdomains und Zertifikatsstrategie ausdrücklich beschreiben.

### Abnahmekriterien und Regressionstests

- [ ] Appwrite bekommt reine Hostnamen in Domainfeldern und gültige URLs in URL-Feldern.
- [ ] Neu erzeugte Funktion und Site sind ohne Einzelkorrektur der Domainliste erreichbar, wenn Wildcard-Routing eingerichtet ist.
- [ ] Zertifikat und Route passen zum erzeugten Host.

### Offene Fragen und Risiken

- Eine Wildcard-DNS-Zone allein erzeugt weder eine Proxy-Route noch ein passendes TLS-Zertifikat.
- Appwrite-Version und ursprüngliche Proxy-Konfiguration sind nicht vollständig dokumentiert.

```markdown
Can you guys check if you're running version 2 or 3 of Traefik? You can check this by Servers, choose your server and then Proxy.

The reason I ask this is because I got everything working but a few days back I saw a issue that someone could not get wildcard certificate to work. He was also getting 404 pages. But I saw in his issue that he was using Traefik version 3 and I'm using version 2.

And after some digging I found out that since version v4.0.0-beta.324 this has been changed to version 3 and I installed Coolify before that so that was de reason why I was running version 2 instead of version 3. Luckily there is a button reset default config and now I'm running version 3. But now I'm also getting 404 pages.

So I check the docs again about the wildcard certificates but that is still for Traefik version 2. And for Traefik 3, according to the [docs](https://doc.traefik.io/traefik/v3.0/routing/routers/#host-and-hostregexp) of Traefik I needed to change ``HostRegexp(`{subdomain:[a-zA-Z0-9]+}.domain.com`)`` to ``HostRegexp(`^.+\.domain\.com$`)`` in my applications compose file and now everything is working again.
```

The domain name is correct on my end; however, Coolify is unable to detect the generated domain. After that I must manually add the generated domain into the service domain and then restart the resource/project.


Updated:
It seems to be working for me now. I've added a new configuration to the Servers Dynamic Configurations. Here's the config in case anyone needs it.

`appwrite-wildcard.yaml`
```yaml
http:
  routers:
    appwrite-wildcard-https:
      entryPoints:
        - https
      service: appwrite-wildcard-service
      rule: 'HostRegexp(`^.+\.fn\.appwrite\.example\.com`) || HostRegexp(`^.+\.site\.appwrite\.example\.com`)'
      tls:
        certresolver: letsencrypt
  services:
    appwrite-wildcard-service:
      loadBalancer:
        servers:
          -
            url: 'http://appwrite:80' # This should be match with service name in the projects/resources
```
