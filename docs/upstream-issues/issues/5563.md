## Aufarbeitung: Authentik-ForwardAuth-Anleitung mit reproduzierbarer Konfiguration erneuern

**Bereich:** Dokumentation / Authentik · **Priorität:** P2 · **Bewertung:** Integration / Dokumentation

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Die Anleitung und Kommentare vermischen eingebetteten/separaten Outpost, falsche Hosts, Netzzugehörigkeit und Middleware-Anbindung. Einzelne erfolgreiche Konfigurationen sind versions- und topologieabhängig. Unsichere TLS-Ausnahmen aus Kommentaren sollen nicht als allgemeiner Lösungsweg übernommen werden.

### Reproduktion / Prüfszenario

1. Frischen Authentik-Teststack und einen harmlosen geschützten Dienst auf demselben Testhost einrichten.
2. Provider, Anwendung und gewählten Outpost explizit zuordnen.
3. ForwardAuth-Ziel aus dem Proxy-Netz prüfen und anschließend abgemeldeten sowie angemeldeten Browserzugriff testen.

### Befunde

- Mehrere Kommentare berichten Erfolg nach korrekter Outpost-Zuordnung und docker_network=coolify.
- Andere Kommentare widersprechen sich dazu, ob der eingebettete Outpost genügt; dies ist hier nicht pauschal verifiziert.
- Das aktuelle Authentik-Template, Proxy-Labelgenerator und dynamische Proxy-Konfiguration sind die lokalen Integrationspunkte.

### Umsetzungsschritte

- [ ] Eine getestete Standardtopologie mit exakten Versionsannahmen und tatsächlichem Outpost-Host dokumentieren.
- [ ] Middlewaredefinition und Zuordnung zum konkreten Router als getrennte Schritte erklären.
- [ ] Varianten für externes Authentik sowie Fehlerdiagnose für 404/Redirect/Netzwerk getrennt darstellen; TLS-Prüfung aktiv halten.

### Abnahmekriterien und Regressionstests

- [ ] Nicht angemeldeter Zugriff wird zur richtigen Authentik-Anmeldung geführt.
- [ ] Erlaubter Benutzer erreicht den Dienst; verweigerter Benutzer bleibt gesperrt.
- [ ] Neustart und zweite geschützte Anwendung ändern die erste Zuordnung nicht.

### Offene Fragen und Risiken

- Einige kopierte Kommentar-URLs enthalten abgelaufene signierte Attachment-Tokens; diese werden nicht in die Analyse übernommen.
- Die Beispiele mit bloßen Middleware-Labelnamen müssen am generierten Router geprüft werden.

````markdown
![Image](https://github.com/user-attachments/assets/a7ae987a-42e3-42a3-a8d9-c9ded7de25c7)

### Steps to Reproduce

1. Follow this [tutorial](https://blog.iltc.io/2025-01-28-authentik-forward-auth-middleware-for-coolify/) **except** for the part where you need to change the port because this is already solved.
2. In this part of the [tutorial](https://blog.iltc.io/2025-01-28-authentik-forward-auth-middleware-for-coolify/#finding-the-authentik-server-host) **be sure** that the name of the `AUTHENTIK_SERVER_HOST` starts with `authentik-server-XXXXXXXXX…:9000/outpost.goauthentik.io/auth/traefik`
3. In the [final part of the tutorial](https://blog.iltc.io/2025-01-28-authentik-forward-auth-middleware-for-coolify/#protecting-services), if you create your service with an **empty docker compose file** just add the following label at the same level as the docker image
```yaml
labels:
      - traefik.http.middlewares.authentik-auth@file
```

Example:
```yaml
services:
  privatebin:
    image: privatebin/nginx-fpm-alpine
    environment:
      - SERVICE_FQDN_PRIVATEBIN_8080
    volumes:
      - 'privatebin_data:/srv/data'
    healthcheck:
      test:
        - CMD-SHELL
        - 'wget -qO- http://127.0.0.1:8080/'
      interval: 5s
      timeout: 20s
      retries: 10
    labels:
      - traefik.http.middlewares.authentik-auth@file
```
3. Restart / Redeploy your service and enter again
````

````markdown
```yaml
http:
  middlewares:
    authentik:
      forwardAuth:
        # outpost as per docs https://docs.goauthentik.io/add-secure-apps/providers/proxy/server_traefik/
        address: 'http://ak-outpost-coolify:9000/outpost.goauthentik.io/auth/traefik'

        authResponseHeaders:
          - X-authentik-username
          - X-authentik-groups

          - X-authentik-name

          - X-authentik-meta-provider
          - X-authentik-meta-app
          - X-authentik-meta-version
  routers:
    ak-outpost-callback:
      rule: 'Host(`auth.domain.wtf`) && PathPrefix(`/outpost.goauthentik.io/`)'
      service: ak-outpost-svc
  services:
    ak-outpost-svc:
      loadBalancer:
        servers:
          - url: 'http://ak-outpost-coolify:9000/outpost.goauthentik.io/'
````
