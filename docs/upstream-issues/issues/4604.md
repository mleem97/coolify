## Aufarbeitung: GHCR-Zugangsdaten beim tatsächlichen Docker-Ausführer verwenden

**Bereich:** Registry / Deployment · **Priorität:** P2 · **Bewertung:** Reproduktion erforderlich

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Der GHCR-Pull funktioniert teilweise auf dem Host, aber nicht aus Coolify. Die Kommentare zeigen verschiedene Ursachen: falscher Host, Login als anderer Benutzer und fehlender Credential-Mount im Helper. Diese Fälle dürfen nicht zu einer einzigen Registry-Störung zusammengefasst werden.

### Reproduktion / Prüfszenario

1. Privates Testimage mit leseberechtigtem Credential vorbereiten.
2. Jeweils als root und als konfigurierter SSH-Nutzer am Build-/Zielserver anmelden und dort einen Pull prüfen.
3. Coolify-Deployment starten und ausschließlich Pfad/Benutzer der geladenen Docker-Konfiguration protokollieren.

### Befunde

- Der Reporter konnte zunächst schon manuell kein Image ziehen; spätere Fälle ziehen manuell erfolgreich.
- Kommentare 2765097937 und 3419538664 beschreiben fehlende oder falsch zugeordnete config.json-Mounts.
- Aktuelle Deployment-Pfade verwenden serverDockerConfigPrefix; DockerRegistryLoginsTest.php und StandaloneDatabaseRegistryTest.php zeigen inzwischen eigene Registry-Unterstützung.

### Umsetzungsschritte

- [ ] Host-, Helper- und dedizierten Build-Server-Pfad mit derselben Credential-Auflösung prüfen.
- [ ] Registryfehlermeldungen sollen Host/Benutzer/fehlende Berechtigung unterscheiden, ohne Secrets zu zeigen.
- [ ] Vorhandene Registryverwaltung bevorzugen und keine Tokens in Compose oder Befehlsargumenten ablegen.

### Abnahmekriterien und Regressionstests

- [ ] Privates GHCR-Image lässt sich im root- und nicht-root-Fall deployen.
- [ ] Falsche Registryrechte erzeugen einen verständlichen Fehler.
- [ ] Docker-Konfiguration bleibt für Unbefugte unlesbar und erscheint nicht im Deploymentlog.

### Offene Fragen und Risiken

- GitHub-App-Repositoryrechte sind keine automatische GHCR-Package-Freigabe.
- Mehrere historische Workarounds sind veraltet oder enthalten Tippfehler.

<summary>Kommentartext</summary>

````markdown
@ZharaskhanAman that is ran inside the helper which is already running as root

I think there are a few issues here

1) when running as non root, the user should be in the docker group, meaning sudo is not needed (the config should be tied to the docker user)
2) coolify will run sudo on the host anyway changing the location of where the current config is (from /home/user to /root
3) deployments copy over the user config, but either users are running sudo docker login or coolify is, meaning the docker user config is empty.
4) coolify installs plugins to /root/.docker instead of /var/local/lib/docker in the helper, this means it manually has to mount the config manually when it could just use ```--use-api-socket``` which auto mounts both the socket and the config
````

</details>
