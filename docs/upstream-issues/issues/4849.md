## Aufarbeitung: Authentik-Ersteinrichtung über den richtigen internen Port routen

**Bereich:** Service-Template / Authentik · **Priorität:** P2 · **Bewertung:** Möglicherweise bereits adressiert

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Das Authentik-Template war über die automatische Domain nicht erreichbar. Ein Kommentar löst den Fall durch Auswahl des internen Ports 9000. Eine öffentliche Host-Port-Freigabe ist für funktionierendes Proxy-Routing nicht grundsätzlich erforderlich.

### Reproduktion / Prüfszenario

1. Aktuelles Authentik-Template ohne zusätzliche öffentliche Ports deployen.
2. Generierte Domain, Service-Port und Proxy-Labels prüfen.
3. Den Initial-Setup-Pfad sowie Anmeldung über HTTPS aufrufen.

### Befunde

- Kommentar 2700711881 berichtet Erfolg mit Port 9000 in der Coolify-Domainzuordnung.
- templates/compose/authentik.yaml verwendet aktuell SERVICE_URL_AUTHENTIKSERVER_9000 und eine neuere Authentik-Version.
- In #5563 wird der frühere Portteil der Anleitung ausdrücklich als bereits gelöst beschrieben.

### Umsetzungsschritte

- [ ] Erstinstallation mit aktuellem Template prüfen und benötigten internen Port in Domain-/Proxy-Erkennung absichern.
- [ ] Falls noch fehlerhaft, Portableitung korrigieren statt pauschal 9000 auf dem Host zu veröffentlichen.
- [ ] Initial-Setup-Link in der Dienstbeschreibung konkret angeben.

### Abnahmekriterien und Regressionstests

- [ ] Initial Setup und Login sind über die konfigurierte HTTPS-Domain erreichbar.
- [ ] Kein zusätzlicher öffentlich gebundener Verwaltungsport nötig.
- [ ] Proxy zeigt auf Port 9000 des richtigen Containers.

### Offene Fragen und Risiken

- Ein korrekter Port behebt keine Authentik-Outpost-/ForwardAuth-Konfiguration.
