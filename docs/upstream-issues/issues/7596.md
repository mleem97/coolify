## Aufarbeitung: Teamweite Deploymenthistorie mit Filtern und laufender Aktualisierung ergänzen

**Bereich:** Dashboard / Deploymenthistorie / Livewire · **Priorität:** P2 · **Bewertung:** Erweiterung

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Gewünscht ist eine eigene Seite in der Navigation, die alle verfügbaren historischen Deployments des Teams mit Projekt-, Server-, Quellen- und Statusfilter zeigt. Der aktuelle Dashboardbaustein zeigt nur kleine Listen aktiver und kürzlich abgeschlossener Deployments. Mehrere angekündigte PRs in der Diskussion belegen keine Übernahme in den untersuchten Stand.

### Reproduktion / Prüfszenario

1. Im aktuellen Dashboard ein Team mit mehreren Projekten, Servern, Quellen und mehr als fünf abgeschlossenen Deployments öffnen.
2. Den bestehenden Überblick mit der geforderten vollständigen Historie und ihren Filterkombinationen vergleichen.
3. Dasselbe als Mitglied mit eingeschränkten Ressourcengrants und mit nur einem Server beziehungsweise einer Quelle prüfen.

### Befunde

- Das Issue fordert ausdrücklich einen Navigationseintrag, vollständige Historie, vier Filter, Liveaktualisierung und ausgeblendete Server-/Quellenfilter bei nur einer Option.
- ActiveDeployments.php begrenzt sowohl die aktive als auch die kürzliche Liste auf fünf Einträge und verwendet für PostgreSQL einen angepassten Abfragepfad.
- ApplicationDeploymentQueue::applicationIdsOwnedByTeam() berücksichtigt auch gelöschte Anwendungen sowie vorhandene Zugriffsscoping-Regeln; diese Logik ist ein passender Ausgangspunkt.
- In Kommentaren werden unter anderem PR #8074 und #11676 genannt; ihre Aussagen sind als Vorschläge zu behandeln. Maintainer Cinzya bestätigt am 13.09.2026 das Ende des Algora-Bountyprogramms.

### Umsetzungsschritte

- [ ] Eine Livewire-Seite samt Navigationseintrag auf Grundlage der bestehenden Deploymentmodelle und Statusdarstellung ergänzen.
- [ ] Filter serverseitig, kombinierbar und in der URL abbilden; Filteroptionen ausschließlich aus sichtbaren Ressourcen beziehen und leere/ungültige Auswahl nach Teamwechsel zurücksetzen.
- [ ] Die Historie paginieren und nur benötigte Spalten laden; Polling darf aktuelle Ansicht, Filter und Seitenposition nicht unkontrolliert verändern.
- [ ] Gelöschte Ressourcen anhand gespeicherter Deploymentnamen verständlich anzeigen; alle noch vorhandenen Historieneinträge anbieten, ohne gelöschte Queuehistorie zu versprechen.

### Abnahmekriterien und Regressionstests

- [ ] Alle für den Benutzer sichtbaren vorhandenen Deployments sind über Seiten erreichbar und nach den vier Dimensionen korrekt filterbar.
- [ ] Andere Teams und Ressourcen außerhalb von Grants sind weder in Daten noch Filteroptionen sichtbar.
- [ ] Statusänderungen werden aktuell angezeigt, während Filter und Navigation stabil bleiben.
- [ ] Bei einer einzelnen Server-/Quellenoption ist der entsprechende Filter ausgeblendet; Tastaturbedienung und mobile Darstellung funktionieren.

### Offene Fragen und Risiken

- Die gewünschte Bedeutung des Quellenfilters muss GitHub-App, GitLab, Deploy-Key, öffentliches Repository und Image-/Dockerfile-Anwendungen eindeutig abbilden.
- Mehrere Kommentare verwenden unpassende Frameworkvorschläge oder behaupten nicht verifizierte PR-Erfolge; sie werden nicht als Implementierungsbeleg übernommen.
- Bountylabels sind keine aktuelle Zahlungszusage.

### Proposed Solution

The root cause is the lack of a dedicated deployment page in the coollabsio/coolify repository, making it difficult for users to track and manage their deployments. This enhancement aims to address this issue by introducing a new deployment page with filtering and live update capabilities.

To implement this, follow these steps:
1. Create a new component `DeploymentsPage` in `src/pages/DeploymentsPage.tsx`.
2. Add a sidebar item in `src/components/Sidebar.tsx` to link to the new page.
3. Implement filtering and live updates in `src/pages/DeploymentsPage.tsx` using React hooks and API calls.

Example code:
```jsx
// src/pages/DeploymentsPage.tsx
import React, { useState, useEffect } from 'react';

const DeploymentsPage = () => {
  const [deployments, setDeployments] = useState([]);
  const [filter, setFilter] = useState({});

  useEffect(() => {
    fetchDeployments();
  }, [filter]);

  const fetchDeployments = async () => {
    const response = await fetch('/api/deployments', {
      method: 'GET',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(filter),
    });
    const data = await response.json();
    setDeployments(data);
  };

  return (
    <div>
      <h1>Deployments</h1>
      <div>
        <label>Filter by project:</label>
        <select
          value={filter.project}
          onChange={(e) => setFilter({ ...filter, project: e.target.value })}
        >
          <option value="">All</option>
          {/* options */}
        </select>
      </div>
      {/* other filters and deployment list */}
    </div>
  );
};

export default DeploymentsPage;
```
