## Aufarbeitung: Datenbankcontainer in Docker eindeutig erkennbar benennen

**Bereich:** Datenbank / Bedienbarkeit · **Priorität:** P3 · **Bewertung:** Erweiterung

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Standalone-Datenbanken verwenden eine UUID als Containername, während viele Service-Templates lesbare Dienstnamen ergänzen. Der Wunsch nach Erkennbarkeit ist nachvollziehbar, eine spontane Umbenennung würde jedoch Backups, Proxy-Ziele und bestehende Automatisierung betreffen.

### Reproduktion / Prüfszenario

1. Eine Standalone-MariaDB und einen mehrteiligen Template-Dienst bereitstellen.
2. docker ps, Compose-Servicenamen, Coolify-Labels und die Anzeige im Dashboard vergleichen.
3. Bestehende Funktionen auf Namensabhängigkeiten untersuchen.

### Befunde

- Original und Kommentar beschreiben die schwer zuzuordnende UUID in docker ps.
- StartPostgresql verwendet den Datenbank-UUID-basierten Containernamen.
- Backup- und andere Verwaltungspfade greifen auf dieselbe Containeridentität zu.

### Umsetzungsschritte

- [ ] Zunächst lesbare vorhandene Labels und die Zuordnung in der UI verbessern.
- [ ] Falls Namen geändert werden, ein versionsfähiges Namensschema mit Migrations- und Rückwärtskompatibilität planen.
- [ ] Container über stabile Labels/IDs suchen, soweit freie Namen unterstützt werden sollen.

### Abnahmekriterien und Regressionstests

- [ ] Administrator kann den Container zuverlässig einer Coolify-Ressource zuordnen.
- [ ] Backup, Restore, Monitoring und Proxy funktionieren vor und nach einer eventuellen Migration.
- [ ] Namenskonflikte und ungültige Docker-Namen werden ausgeschlossen.

### Offene Fragen und Risiken

- Umbenennung ist eine Verhaltensänderung, kein sicherer kosmetischer Einzeiler.
- Fremde Skripte können sich bereits auf UUID-Namen verlassen.
