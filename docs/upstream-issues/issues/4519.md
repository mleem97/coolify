## Aufarbeitung: Eigene PostgreSQL-Konfiguration lesbar bereitstellen

**Bereich:** Datenbank / PostgreSQL · **Priorität:** P1 · **Bewertung:** Möglicherweise bereits adressiert

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Ein bestehender PostgreSQL-Container konnte die nachträglich hinzugefügte Konfigurationsdatei nicht lesen. Am aktuellen Stand setzt StartPostgresql nach dem Schreiben ausdrücklich chmod 644; der frühere umask-bedingte Fehlerpfad ist damit wahrscheinlich adressiert.

### Reproduktion / Prüfszenario

1. Bestehende Testdatenbank mit restriktiver Host-umask betreiben.
2. Eine eigene PostgreSQL-Konfiguration ergänzen und neu starten.
3. Datei-Modus sowie SHOW config_file und die gewünschte Einstellung kontrollieren.

### Befunde

- Die Logs melden Permission denied für /etc/postgresql/postgresql.conf.
- Kommentare grenzen die Dateierstellung in StartPostgresql ein und nennen manuelle chmod-Workarounds.
- StartPostgresql::add_custom_conf schreibt inzwischen custom-postgres.conf und setzt danach chmod 644.

### Umsetzungsschritte

- [ ] Den vorhandenen Rechtefix auf neu angelegte und bereits bestehende Datenbanken prüfen.
- [ ] Falls ein Restfehler besteht, Verzeichnis-Traversierrechte und nicht-root-Sudo-Pfad untersuchen.
- [ ] Regressionsfall mit restriktiver umask ergänzen, falls noch nicht abgedeckt.

### Abnahmekriterien und Regressionstests

- [ ] PostgreSQL startet mit eigener Konfiguration auch nach wiederholtem Speichern.
- [ ] Gewünschte Werte sind tatsächlich aktiv.
- [ ] Kein manuelles chmod und kein Verlust vorhandener Daten erforderlich.

### Offene Fragen und Risiken

- Leserechte der Datei allein lösen keine fehlenden Traversierrechte übergeordneter Verzeichnisse.
- Fehlende Runtime-Prüfung verhindert eine endgültige Erledigt-Markierung.

````markdown
**Context:**
In Coolify 4.0.0, you can add custom PostgreSQL configuration variables through the "Custom PostgreSQL Configuration" field. This field is essentially a shortcut that creates the file /data/coolify/databases/<your_service_uid>/custom-postgres.config.
However, when deploying or restarting the container with custom configuration, the logs return:

```
PostgreSQL Database directory appears to contain a database; Skipping initialization
2024-12-01 14:23:26.563 GMT [1] LOG:  could not open configuration file "/etc/postgresql/postgresql.conf": Permission denied
2024-12-01 14:23:26.563 GMT [1] FATAL:  configuration file "/etc/postgresql/postgresql.conf" contains errors
```

**Temporary Workaround:**

1. Deploy or restart the PostgreSQL container with the custom configuration already included
2. Access the host machine terminal (via Coolify terminal or SSH)
3. Run: `sudo chmod 755 /data/coolify/databases/<your_service_uid>/custom-postgres.config`
4. (Optional) Restart your PostgreSQL container again

**How to find your PostgreSQL service UID if you've renamed the service:**

1. Access the service logs
2. The UID will be shown in the header

**Reference:**
Originally reported by @GottZ in #4519

**Obs**
It worked for me too !
````
