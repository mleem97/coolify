## Aufarbeitung: Wiederverwendbaren Mailserver-Stack für mehrere Kundendomains vervollständigen

**Bereich:** Service-Templates / E-Mail / TLS · **Priorität:** P2 · **Bewertung:** Erweiterung

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Eine Agentur möchte einen wiederverwendbaren Mailserver mit dauerhaft gespeicherten Postfächern, Konfiguration und Zertifikaten sowie passender Coolify-Integration. Im heutigen Repository existiert bereits ein Stalwart-Template als möglicher Ausgangspunkt. Entscheidend ist die geprüfte vollständige Einrichtung einschließlich Mailprotokollen und Zertifikatserneuerung; ein weiterer ungeprüfter YAML-Eintrag würde den Bedarf nicht abschließen.

### Reproduktion / Prüfszenario

1. Das vorhandene Stalwart-Template mit festem Image auf einem isolierten Testhost bereitstellen und die vorhandenen Volumes, veröffentlichten Mailports und Web-UI prüfen.
2. Zwei Testdomains mit getrennten Konten und Aliasen einrichten und ausschließlich kontrollierte Testnachrichten zwischen eigenen Empfängern senden.
3. Mail-TLS und Web-HTTPS getrennt prüfen; Neustart, Zertifikatserneuerung und Wiederherstellung aus Backup durchspielen.

### Befunde

- Das Issue ist aus #8255 ausgegliedert und nennt Docker Mailserver oder Mailu nur als Beispiele; gefordert sind ein gewarteter Stack, persistente Daten und Proxy-/Zertifikatskompatibilität.
- templates/compose/stalwart.yaml verwendet stalwartlabs/stalwart:v0.16.13, persistente Konfigurations-/Datenvolumes, Webport 8080 und veröffentlichte SMTP-/IMAP-/POP3-/Sieve-Ports.
- Die offizielle Stalwart-Proxy-Dokumentation unterscheidet Webproxying und die TLS-Behandlung der Mailprotokolle. Ein funktionierendes HTTPS-Webinterface belegt deshalb noch kein korrektes SMTP-/IMAP-TLS.
- Mehrere Kommentare verweisen auf eingereichte Templates; ein Autor berichtet die Schließung von #10583. Maintainer bestätigt am 13.09.2026 das Ende der Algora-Bountys.

### Umsetzungsschritte

- [ ] Zunächst das bestehende Stalwart-Angebot gegen die gewünschten Betriebsabläufe prüfen und die fehlenden Teile konkret benennen, bevor ein zweiter Stack ausgewählt wird.
- [ ] DNS- und Netzwerkvoraussetzungen für MX, SPF, DKIM, DMARC, Reverse-DNS und erreichbare Mailports in der Einrichtung nachvollziehbar machen.
- [ ] Ein konsistentes Konzept für Zertifikatsbezug, Persistenz und Erneuerung der Mailprotokolle definieren; die Webproxy-Zertifikate nicht still als ausreichend voraussetzen.
- [ ] Backup-/Restorepfade für Maildaten und Konfiguration sowie einen getesteten Mehrdomainablauf dokumentieren; keine produktiven Kundendomains automatisch ändern.

### Abnahmekriterien und Regressionstests

- [ ] Zwei getrennte Testdomains können authentisiert senden und empfangen; unberechtigtes Weiterleiten wird abgewiesen.
- [ ] Postfächer, Einstellungen und notwendige Zertifikatsdaten bleiben nach Neuerstellung des Containers erhalten.
- [ ] Weboberfläche und Mailprotokolle liefern jeweils gültige Zertifikate; Erneuerung wird ohne manuellen Verlust von Konfiguration nachgewiesen.
- [ ] Ein vollständiger Wiederherstellungstest stellt Konten und Nachrichten aus dem gesicherten Zustand wieder her.

### Offene Fragen und Risiken

- Provider-Portblockaden, DNS und IP-Reputation liegen außerhalb einer reinen Compose-Datei und müssen als konkrete Voraussetzungen dargestellt werden.
- Die Eignung des aktuellen Stalwart-Templates für alle gewünschten Abläufe ist noch nicht zur Laufzeit verifiziert.
- Die Wahl eines weiteren Mailserverprodukts ist nur nötig, wenn eine nachgewiesene Anforderung mit dem bestehenden Angebot nicht abgedeckt wird.

### Proposed Solution

The root cause is the lack of a reusable email server template in Coolify, making it difficult for users to manage client email domains. This issue requires creating a self-hosted email server stack with persistent volumes.

To implement this, follow these steps:
1. Create a new Docker Compose file (`docker-compose.email.yml`) in the `templates` directory.
2. Add a Mailserver service using Docker Mailserver image.
3. Configure persistent volumes for mailboxes, configuration, and certificates.

Example code in `templates/docker-compose.email.yml`:
```yml
version: '3'
services:
  mailserver:
    image: docker-mailserver/docker-mailserver
    volumes:
      - ./mailboxes:/var/mail
      - ./config:/etc/mailserver
      - ./certs:/etc/ssl/certs
```
Testing suggestions: deploy the new template and verify email sending and receiving functionality.
