## Aufarbeitung: Schlüssellöschung mit funktionierendem Bestätigungsdialog prüfen

**Bereich:** Sicherheit / Oberfläche · **Priorität:** P2 · **Bewertung:** Reproduktion erforderlich

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Die alte Keys-&-Tokens-Oberfläche löscht einen Schlüssel nicht; die gemeldete Browserwarnung betrifft den Fokus unter aria-hidden. Eine solche Warnung beweist allein keinen abgebrochenen Löschrequest. Aktuell kommen außerdem legitime Sperren für verwendete Schlüssel hinzu.

### Reproduktion / Prüfszenario

1. Unbenutzten Testschlüssel anlegen und ausschließlich per Tastatur löschen.
2. Fokusverlauf, Dialogzustand und Livewire-Request beobachten.
3. Einen verwendeten Schlüssel als Negativfall und den Ablauf nach wiederholtem Öffnen/Schließen testen.

### Befunde

- Originalmeldung: beta.397 und aria-hidden-Warnung, ohne Serverfehler.
- Kommentar 4298650813 verweist auf PR 9734; dessen Status wurde nicht verifiziert.
- PrivateKey/Show und zugehörige Blade-Datei enthalten heute einen Bestätigungsdialog, Policy-Prüfung und Sperrgrund für verwendete Schlüssel.

### Umsetzungsschritte

- [ ] Dialogfokus vor dem Verbergen zurückgeben und vorhandene Modal-Komponente korrekt verwenden.
- [ ] Falls kein Request gesendet wird, Event-/Livewire-Pfad isolieren; falls serverseitig blockiert, den konkreten Grund anzeigen.
- [ ] Keine Abhängigkeitssperre zur Behebung eines UI-Problems entfernen.

### Abnahmekriterien und Regressionstests

- [ ] Unbenutzter Schlüssel wird nach bewusster Bestätigung genau einmal gelöscht.
- [ ] Fokus kehrt auf ein sichtbares sinnvolles Element zurück; Tastaturbedienung bleibt möglich.
- [ ] Verwendete oder fremde Schlüssel bleiben geschützt und zeigen einen verständlichen Sperrgrund.

### Offene Fragen und Risiken

- Historischer Dialog und heutige Oberfläche unterscheiden sich deutlich.
- Der im Original erwähnte ARIA-Hinweis kann ein Begleitsymptom sein.
