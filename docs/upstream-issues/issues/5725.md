## Aufarbeitung: Git-LFS-Downloads mit einer auf dem Server installierten privaten CA prüfen

**Bereich:** Git und TLS · **Priorität:** P2 · **Bewertung:** Möglicherweise bereits adressiert

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Git-Klonen über SSH funktioniert, der anschließende HTTPS-LFS-Download vertraut der privaten GitLab-CA im Helper nicht. Im heutigen Code existiert bereits ein Mount des Host-CA-Bundles; der LFS-Pfad muss damit gezielt nachgetestet werden.

### Reproduktion / Prüfszenario

1. Auf einem Testserver eine private GitLab-CA vertrauenswürdig installieren und ein Repository per SSH-Deploy-Key anbinden.
2. Ein LFS-Objekt hinzufügen und den Deployment-Helper mit dem normalen Git/LFS-Ablauf starten.

### Befunde

- Meldung beta.414: x509: certificate signed by unknown authority; Maintainer-Diskussion grenzt den Host-Trust vom Trust im Helper ab.
- app/Jobs/ApplicationDeploymentJob.php: hostCaBundleMount() bindet ein vorhandenes Server-CA-Bundle schreibgeschützt im Helper ein.
- app/Models/Application.php führt Git LFS bei vorhandenen LFS-Dateien weiterhin im Klonablauf aus.

### Umsetzungsschritte

- [ ] Aktuell gepinnte Helper-Version darauf prüfen, wie sie coolify-host-ca-certificates.crt aktiviert; der Mount allein beweist die Nutzung durch Git LFS noch nicht.
- [ ] LFS mit Debian- und alternativen unterstützten CA-Pfaden sowie getrenntem Buildserver nachtesten.
- [ ] Bei verbleibender Lücke CA-Übernahme im Helper beziehungsweise dessen Initialisierung korrigieren und Upstream-Abhängigkeit dokumentieren.

### Abnahmekriterien und Regressionstests

- [ ] SSH-Klon und HTTPS-LFS-Download funktionieren bei korrekt installierter privater CA.
- [ ] Ein unbekanntes oder ungültiges Zertifikat wird weiterhin zurückgewiesen.
- [ ] Kein globales Abschalten der TLS-Prüfung; fehlendes CA-Bundle bricht normale öffentliche Git-Quellen nicht.

### Offene Fragen und Risiken

- Helper-Implementierung befindet sich in coollabsio/coolify-helper und ist nicht Teil dieses Forks.
- Der ursprüngliche Fehler wurde in dieser Aufarbeitung nicht live reproduziert.

### Error Message and Logs

I use a self hosted gitlab, with a self-signed TLS certificate. My repo contains some files that are LFS. Coolify was able to clone the repo with a deploykey over ssh, but GitLab only supports LFS over http/https. This however fails with the following error:

3. CA cert installed on debian as trusted
4. Project with Gitlab via deploykey (ssh)
5. Try to deploy: **success**
6. Setup LFS for the repo and push some LFS files
7. Try to deploy again on Coolify: **fails**
