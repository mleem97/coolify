# Upstream #5626: GitHub-Quelleneinrichtung ohne gültige öffentliche Instanzadresse abfangen

## Aufarbeitung: GitHub-Quelleneinrichtung ohne gültige öffentliche Instanzadresse abfangen

**Bereich:** Git-Quellen / Onboarding · **Priorität:** P2 · **Bewertung:** Reproduktion erforderlich

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Eine frische Instanz erzeugt bei GitHub-Source-Einrichtung einen Fehler, solange die Instanzdomain fehlt und localhost als Basis verwendet wird. Die aktuelle Einrichtung wählt Domain, IP oder app.url als Webhookendpoint; ungültige/unerreichbare Standardwerte müssen sichtbar behandelt werden.

### Reproduktion / Prüfszenario

1. Frische Testinstanz ohne eingetragene Instanzdomain öffnen.
2. GitHub-Quelle mit Organisation und System-wide-Schalter anlegen.
3. Dasselbe nach Eintragung einer gültigen Testdomain wiederholen und den erzeugten Callback-/Webhookhost vergleichen.

### Befunde

- Kommentar 2810787422 bestätigt, dass Setzen der Instance Domain den Ablauf beim Reporter ermöglicht.
- Source/Github/Create und Change sind heute getrennte Schritte.
- Change wählt fqdn, ipv4, ipv6 oder config(app.url) für webhook_endpoint; ein Fallback kann also weiterhin eine nicht öffentlich erreichbare Adresse liefern.

### Umsetzungsschritte

- [ ] Vor automatischer GitHub-App-Erstellung die Callback-/Webhookbasis prüfen.
- [ ] Eine fehlende geeignete Adresse mit einem direkten verständlichen Konfigurationshinweis erklären.
- [ ] Manuelle Installation und lokale Entwicklungsfälle bewusst getrennt behandeln.

### Abnahmekriterien und Regressionstests

- [ ] Neue Installation zeigt bei fehlender Adresse einen erklärten Zustand statt generischem Fehler.
- [ ] Mit gültiger Adresse werden funktionsfähige Callback-/Webhook-URLs erzeugt.
- [ ] Systemweite Quellen bleiben auf dafür berechtigte Benutzer begrenzt.

### Offene Fragen und Risiken

- Öffentliche Erreichbarkeit lässt sich nicht allein mit einer URL-Syntaxprüfung beweisen.
- Der alte Screenshot enthält die vollständige Exception nicht als Text.
