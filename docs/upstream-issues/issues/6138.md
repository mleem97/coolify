## Aufarbeitung: Logs nach externer Container-Umbenennung anhand der Ressourcenzuordnung wiederfinden

**Bereich:** Logs und Containerzuordnung · **Priorität:** P2 · **Bewertung:** Möglicherweise bereits adressiert

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Nach Umbenennung in Portainer sucht Coolify laut Meldung nach dem alten Containernamen. Heute ermittelt der Logbereich Container dynamisch über Ressourcenlabels; der konkrete Umbenennungsfall, besonders bei Legacy-Containern, muss nachgetestet werden.

### Reproduktion / Prüfszenario

1. Testcontainer einer Anwendung beziehungsweise eines Services extern umbenennen, Labels und ID unverändert lassen.
2. Bereits geöffnete Logansicht aktualisieren und danach neu öffnen; Produktion und Preview getrennt prüfen.

### Befunde

- Erstbericht beta.419 enthält keine Kommentare oder Ressourcentyp-Angabe.
- Logs::loadServerContainers nutzt getCurrentApplication/Service/DatabaseContainerStatus; containersOwnedBy() liest Docker-Container über Besitzerlabels.
- GetLogs baut docker logs mit dem ausgewählten Container auf; RuntimeLogsContainerRefreshTest.php behandelt dynamische Aktualisierung.

### Umsetzungsschritte

- [ ] Umbenennung als Regression der dynamischen Containerermittlung ergänzen.
- [ ] Wenn die Auswahl am alten Namen hängt, anhand unveränderlicher Container-ID und Ressourcenlabel neu zuordnen.
- [ ] Vor Logzugriff weiterhin Team-, Ressourcen- und Serverberechtigung prüfen; keine beliebige ID aus dem Browser akzeptieren.

### Abnahmekriterien und Regressionstests

- [ ] Logs bleiben nach Umbenennung ohne Neuanlage der Ressource zugänglich.
- [ ] Ein neu erzeugter Container nach Deployment wird ebenfalls korrekt gewählt.
- [ ] Umbenennung erlaubt keinen Zugriff auf fremde Container oder Teams; alte Legacy-Labels werden nachvollziehbar behandelt.

### Offene Fragen und Risiken

- Historische Container ohne neue UUID-Labels können weiterhin auf Namenskonventionen angewiesen sein.
- Außerhalb Coolify vorgenommene Änderungen können weitere Verwaltungsfunktionen beeinflussen, die hier separat zu prüfen sind.
