# Upstream #5878: Deaktiviertes Auto-Deploy muss Git-Webhooks für Compose-Anwendungen stoppen

## Aufarbeitung: Deaktiviertes Auto-Deploy muss Git-Webhooks für Compose-Anwendungen stoppen

**Bereich:** Git-Webhooks · **Priorität:** P2 · **Bewertung:** Möglicherweise bereits adressiert

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Ein Commit soll bei deaktiviertem Auto-Deploy kein Deployment auslösen. Im aktuellen Code prüfen die unterstützten Git-Webhook-Handler Application::isDeployable(); ein Regressionstest für deaktiviertes Auto-Deploy existiert bereits.

### Reproduktion / Prüfszenario

1. Compose-Anwendung mit manuellem Git-Webhook anlegen und Auto-Deploy ausschalten.
2. Gültig signiertes Push-Ereignis senden; anschließend mit eingeschalteter Option wiederholen.

### Befunde

- Originalbericht beta.418 enthält keine Kommentare oder Providerdetails.
- app/Models/Application.php: isDeployable() liest is_auto_deploy_enabled.
- Github-, Gitlab-, Gitea- und Bitbucket-Webhook-Controller prüfen diesen Status; tests/Feature/Webhook/ManualWebhookApplicationLookupTest.php enthält den Fall auto deploy disabled.

### Umsetzungsschritte

- [ ] Vorhandenen Schutz mit dem Compose-Buildpack und jedem betroffenen Webhook-Typ nachtesten.
- [ ] Bei Restfehlern prüfen, ob der verwendete URL tatsächlich ein Git-Webhook oder ein expliziter Deploy-API-Aufruf ist.
- [ ] UI-Persistenz und API-Schreibpfad der Einstellung mit der Webhook-Entscheidung zusammen prüfen.

### Abnahmekriterien und Regressionstests

- [ ] Deaktiviert: kein Queue-Eintrag nach gültigem Push-Webhook.
- [ ] Aktiviert: passendes Repository und richtiger Branch deployen genau einmal.
- [ ] Manuelle Deploys bleiben möglich; ungültige Signaturen bleiben abgewiesen.

### Offene Fragen und Risiken

- Der genaue Git-Anbieter und Webhook-Endpunkt fehlen im Bericht.
- Ein absichtlich ausgeführter Deploy-API-Aufruf kann fachlich andere Regeln haben als Auto-Deploy.
