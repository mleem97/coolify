## Aufarbeitung: Echte Zeilenumbrüche und wörtliche Backslash-n in Umgebungsvariablen verlustfrei erhalten

**Bereich:** Umgebungsvariablen · **Priorität:** P2 · **Bewertung:** Reproduktion erforderlich

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Bei einem privaten Schlüssel werden Backslashes mehrfach escaped. Die Diskussion unterscheidet Is Literal allein von Is Literal plus Is Multiline mit echten Zeilenumbrüchen; letzteres funktionierte bei einem späteren Nutzer.

### Reproduktion / Prüfszenario

1. Synthetischen mehrzeiligen Wert und separat die Zeichenfolge Backslash+n als ENV speichern.
2. Jeweils Normal-, Literal- und Multiline-Modus testen und die Bytes im Zielcontainer vergleichen, ohne echte Schlüssel zu protokollieren.

### Befunde

- Kommentar vom 11.06.2025 meldet zusätzliche Backslashes trotz Is Literal.
- Kommentar vom 20.09.2025 bestätigt echte mehrzeilige Eingabe mit Literal und Multiline.
- app/Models/EnvironmentVariable.php unterscheidet literal/multiline; tests/Unit/ComposeEnvFileEscapingTest.php prüft echte Zeilenumbrüche und Backslashes.

### Umsetzungsschritte

- [ ] Einen eindeutigen Byte-Roundtrip vom Formular über verschlüsselte Speicherung bis zur Compose-ENV-Datei prüfen.
- [ ] Doppelte Serialisierung im betroffenen Build- oder Laufzeitpfad entfernen, sofern reproduziert.
- [ ] Hilfetext klar zwischen echtem Zeilenumbruch und wörtlichem Backslash+n unterscheiden lassen.

### Abnahmekriterien und Regressionstests

- [ ] Containerwert entspricht bytegenau der gewählten Eingabesemantik.
- [ ] Wiederholtes Öffnen und Speichern fügt keine weitere Escape-Ebene hinzu.
- [ ] Dollarzeichen, Anführungszeichen, CRLF und leere Zeilen bleiben kontrolliert; Logs enthalten keine Secrets.

### Offene Fragen und Risiken

- JSON-Logdarstellung escaped Backslashes zusätzlich und ist kein ausreichender Bytevergleich.
- Ein pauschales Ersetzen aller Backslash+n würde legitime wörtliche Werte verändern.

### Error Message and Logs

In the Coolify environment, if we store an environment variable that includes "\n" directly from the source code, the environment value becomes "\\\\n"  which is a bug.


### Steps to Reproduce

1. Store information containing newline characters (\n) in Environment Variables.
