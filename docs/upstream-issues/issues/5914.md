## Aufarbeitung: Gespeicherte PostgreSQL-Host-Authentifizierung an den Container übergeben

**Bereich:** Datenbankkonfiguration · **Priorität:** P2 · **Bewertung:** Konkreter Codebefund

**Prüfgrundlage:** statische Prüfung von Meldung, abrufbarer Diskussion und Code bei `30335d80866ff3391d899cf4ccb599b696f47b7e`. Keine Laufzeitreproduktion oder Fehlerbehebung in dieser Aufarbeitung.

### Problem und Abgrenzung

Die Oberfläche speichert postgres_host_auth_method, der aktuelle Startpfad fügt daraus jedoch keine POSTGRES_HOST_AUTH_METHOD-Umgebungsvariable hinzu. Zusätzlich ist Erstinitialisierung von bereits vorhandenen PostgreSQL-Daten zu unterscheiden.

### Reproduktion / Prüfszenario

1. Neue PostgreSQL-Ressource ohne bereits initialisiertes Volume erstellen und Host Auth Method setzen.
2. Generierte Compose-Umgebung und initiale pg_hba.conf prüfen; danach Wert bei vorhandenem Volume ändern und Verhalten separat dokumentieren.

### Befunde

- app/Livewire/Project/Database/Postgresql/General.php speichert postgres_host_auth_method.
- app/Actions/Database/StartPostgresql.php: generate_environment_variables() ergänzt POSTGRES_USER, POSTGRES_PASSWORD und POSTGRES_DB, aber nicht den gespeicherten Auth-Method-Wert.
- Das Modell verwendet den Wert im Konfigurationshash; die Meldung nennt trotz Einstellung weiterhin scram-sha-256.

### Umsetzungsschritte

- [ ] Gespeicherten nichtleeren Wert konsistent als POSTGRES_HOST_AUTH_METHOD übernehmen; ausdrücklich gesetzte Runtime-ENV priorisiert behandeln.
- [ ] Zulässige Werte validieren und UI-Hinweis für bereits initialisierte Datenbanken ergänzen.
- [ ] Keine vorhandene pg_hba.conf stillschweigend umschreiben und keine schwächere Authentifizierung als Standard einführen.

### Abnahmekriterien und Regressionstests

- [ ] Neues Volume erhält den gewählten unterstützten Auth-Modus.
- [ ] Explizite Runtime-ENV überschreibt den Formular-Default konsistent; leere Einstellung nutzt den Image-Standard.
- [ ] Bestehende Daten bleiben erhalten und die Oberfläche erklärt, dass ein ENV-Wechsel nicht automatisch die bestehende Konfigurationsdatei migriert.

### Offene Fragen und Risiken

- Image-Version und Initialisierungszustand beeinflussen die Wirkung des Parameters.
- Der Bericht fordert teils schwächere Methoden; sichere Voreinstellungen müssen erhalten bleiben.

### Error Message and Logs

## The Bug

I was trying to change the `POSTGRES_HOST_AUTH_METHOD` via the Coolify GUI, but it never seems to reflect in the actual container configuration.

The `/var/lib/postgresql/data/pg_hba.conf` file will always be the default `scram-sha-256`, as per the [postgres image environment variable options](https://hub.docker.com/_/postgres), instead of the one we set in the `Configuration > Host Auth Method` input field within Coolify.

The last line will always be this.

```bash
host all all all scram-sha-256
```

## Expected Result

It should match the value we set in step (2) of the "Steps to Reproduce" section like so:

```bash
host all all all password
```

### Steps to Reproduce

1. Create a new PostgreSQL database.
2. Set the `Host Auth Method` to `password` or `md5`
3. Go to the Terminal tab and do `cat /var/lib/postgresql/data/pg_hba.conf`

## Workaround
